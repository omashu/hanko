# Hanko — подключение AnimeLib как источника аниме (продолжение)

Прикладывай этот файл + свежий zip проекта в начало нового чата.

## Контекст

В Hanko сейчас два источника аниме — AniLibria и AnimeOn. Пользователь хочет
третий — **AnimeLib** (animelib.org), в первую очередь ради того, что там
у части серий реально есть **4K** (2160p), а не только 720/1080, как у уже
подключённых источников.

## Что уже подтверждено (реальными ответами API, не догадками)

Бэкенд API называется `hapi.hentaicdn.org` (сайт animelib.org — просто
фронтенд поверх него; судя по домену, это та же инфраструктура, что и у
MangaLib/RanobeLib — общий "*Lib"-холдинг). Защита `ddos-guard` в заголовках
есть, но обычные GET-запросы проходят без челленджа — можно дёргать напрямую
через `fetch()`, как и остальные источники в проекте.

### 1. Поиск тайтла
```
GET https://hapi.hentaicdn.org/api/anime?q=<query>&fields[]=rate&fields[]=rate_avg&fields[]=releaseDate
```
Отдаёт `{ data: [...] }`, у каждого элемента: `id`, `name` (англ), `rus_name`,
`slug_url` (это и есть id тайтла для остальных запросов, вида
`10696--rezero-kara-hajimeru-isekai-seikatsu-anime`), `cover.default`/`cover.thumbnail`
(полные абсолютные URL на `cover.hentaicdn.org`), `rating.averageFormated`,
`status.label` (Онгоинг/Завершён), `type.label`.

### 2. Список серий тайтла
```
GET https://hapi.hentaicdn.org/api/episodes?anime_id=<slug_url>
```
Отдаёт `{ data: [...] }`, у каждой серии: `id` (это **id конкретной серии**,
отдельный от anime_id!), `number`, `number_secondary`, `season`, `anime_id`,
`created_at`, `item_number`. Пагинация не проверялась (у тайтла в примере
25 серий уместилось в один ответ без вопроса про страницы — возможно, отдаёт
сразу всё, не проверено на тайтле с сотнями серий).

### 3. Детали одной серии — здесь всё интересное
```
GET https://hapi.hentaicdn.org/api/episodes/<episode_id>
```
(id именно серии из п.2, **не** `anime_id`). Отдаёт `{ data: {..., players: [...] } }`.

`players[]` — это список вариантов озвучки/перевода для серии, каждый со
своей командой (`team.name`, например "AniLibria.TV", "AniDUB", "Crunchyroll",
"SHIZA Project" и т.д.) и `translation_type.label` (`Озвучка` или `Субтитры`).
У каждого элемента поле **`player`** — тип плеера:

- **`"player": "Kodik"`** — тут только `src` вида
  `//kodikplayer.com/seria/139183/9641b32e8031422f6a9acc2537cd1fc9/720p` —
  **это та же самая стена, в которую уже упирались с отдельной идеей "подключить
  Kodik" (см. другой хэндофф в проекте, тема закрыта как тупиковая) — эти
  варианты просто игнорируем, не пытаемся их доставать.**
- **`"player": "Animelib"`** — вот это то, что нужно. У таких элементов есть
  `video.quality[]` — массив **прямых mp4-файлов** по разным разрешениям:
  ```json
  "video": {
    "id": 88894,
    "quality": [
      { "href": "/uploads/converted_videos/anime/10696/players/88894/026a...d_2160.mp4", "quality": 2160, "bitrate": 1797 },
      { "href": "/uploads/converted_videos/anime/10696/players/88894/026a...d_1080.mp4", "quality": 1080, "bitrate": 3000 },
      { "href": "/uploads/converted_videos/anime/10696/players/88894/026a...d_720.mp4",  "quality": 720,  "bitrate": 1400 },
      { "href": "/uploads/converted_videos/anime/10696/players/88894/026a...d_360.mp4",  "quality": 360,  "bitrate": 600 }
    ]
  }
  ```
  **`href` — относительный путь, без домена.** Не у всех вариантов есть 2160
  (в примере из 6 animelib-вариантов у одного было только 720/360) — 4K,
  похоже, зависит от конкретной команды перевода, не гарантирован всегда.
  Субтитры (если есть) — уже с **полным** доменом:
  `https://api.cdnlibs.org/uploads/subtitles/<id>/<file>.vtt` (и `.ass`).

## Единственное, чего не хватает — на этом остановились

Не подтверждён домен, который нужно подставить перед относительным `href`
у видео. По аналогии с субтитрами (`api.cdnlibs.org`) — подозрение, что видео
тоже там, но это не проверено. Пользователю дана инструкция: открыть серию
именно с плеером **Animelib** (не Kodik), реально запустить проигрывание,
в Network найти сам запрос на .mp4 (фильтр Media или "mp4"), прислать полный
Request URL + заголовки запроса — **ответ ещё не получен, разговор прервался
из-за лимита сообщений**.

## Что делать дальше в новом чате

1. Первым делом — дождаться/запросить у пользователя этот самый URL
   (полный, с доменом) конкретного .mp4-запроса из вкладки Network. Без этого
   двигаться дальше бессмысленно — можно ошибиться с доменом и городить
   заведомо нерабочий код.
2. Как только домен известен — реализовать по образцу уже существующих
   источников манги/аниме в `main.js` (см. AniLibria/AnimeOn/WaManga для
   стиля): `alSearch()`/`animelibSearch` (через `/api/anime?q=`),
   `animelibEpisodes(slugUrl)` (через `/api/episodes?anime_id=`, для каждой
   серии дальше дёргать `/api/episodes/<id>` за деталями — either сразу при
   получении списка серий, either лениво при открытии конкретной серии, как
   сейчас устроено резолвление озвучек у AnimeOn — **сверить с текущим кодом,
   какой из двух паттернов уже используется, и повторить тот же, а не
   выдумывать третий**).
3. В сопоставлении "серия → варианты озвучки" — **брать только элементы
   `players[]`, где `"player": "Animelib"` и есть `video.quality`, отбрасывать
   `"player": "Kodik"` полностью** (нет смысла даже пытаться — тупик уже
   пройден отдельно).
4. Подключить как третий источник в `buildUnifiedAnimeEpisodes`-подобную
   логику (сейчас там уже сводятся AniLibria + AnimeOn по номеру серии) — 
   сверить актуальную сигнатуру этой функции в свежем коде, добавить туда
   же ещё один источник, а не городить отдельный параллельный путь.
5. Скорее всего понадобится добавить `Referer: https://animelib.org/` (или
   похожий) в заголовки запроса к самому mp4/API — по аналогии с тем, как
   для остальных источников уже прописаны Referer/Origin в `setupRequestHeaders()`
   /аналогичном месте в `main.js`. Добавить домены `hapi.hentaicdn.org`,
   `cover.hentaicdn.org`, `api.cdnlibs.org` (и домен видео, когда узнаем) в
   список разрешённых.
